## 结论

Pojun 是仍在发版的 AGPL-3.0 自主渗透平台。被审树上有规划者／执行者循环、PostgreSQL 双图、目标未达成时拒绝 `goal_met`、流量证据 SHA-256，以及一套正则拦截。这些都是源码里的机制，不是运行结果。

## 2. 架构与控制面

角色不互聊。planner 被图变更或心跳唤醒，每轮是新的模型会话；跨轮计划在进程内 `todos` 映射，重启即丢（[agent/planner.go#L50-L59](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/agent/planner.go#L50-L59)）。worker 从 frontier 取意图，`ClaimIntent` 用一条 `UPDATE ... state='open'` 做领取（[db/exploration.go#L1450-L1458](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/db/exploration.go#L1450-L1458)、[server/engine.go#L1398-L1453](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/server/engine.go#L1398-L1453)）。mainagent 工具集含 `steer_work`、`add_intent`、`set_goals`（[agent/tools_insert.go#L770-L784](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/agent/tools_insert.go#L770-L784)）。

状态在 PostgreSQL：资产图与探索图（goal、intent、fact、finding）。写回前按 own／source／foreign 分类，默认拒绝 source 与 foreign（[db/task_scope_guard.go#L7-L24](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/db/task_scope_guard.go#L7-L24)、[agent/tools.go#L2126-L2143](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/agent/tools.go#L2126-L2143)）。分类查询失败时函数返回空串，调用方继续写。开关 `scope_write_guard` 默认 true（[server/task_llm.go#L701-L711](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/server/task_llm.go#L701-L711)）。

`goal_met` 在还有未 `met` 目标时直接返回错误，不把任务标完成（[agent/tools.go#L1787-L1811](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/agent/tools.go#L1787-L1811)）。全部目标已 `met` 时，自主推进还可以再加一层目标而不收工（[server/engine.go#L1365-L1372](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/server/engine.go#L1365-L1372)）。未完成可以以 timeout 等终态结束。README 的目标闸门描述与这段代码同向。

工具面分两层。领域工具在 `PlannerTools`／`WorkerTools`／`MainAgentTools`（[agent/tools.go#L2957](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/agent/tools.go#L2957)、[agent/tools_insert.go#L709](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/agent/tools_insert.go#L709)）。Shell、读文件等来自 norma。worker 还有 `http_request`、`session_login`、`job_start`、`poc_scaffold`、`listener_start`。

沙箱、审批、范围：

- 没有把单次工具调用放进单独的用户、seccomp 或一次性容器。Docker 镜像的 `ENTRYPOINT` 是 root 入口脚本，文件里没有 `USER`（[Dockerfile#L112-L119](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/Dockerfile#L112-L119)）。

- 未命中规则时，兜底裁判只在 `llm_judge_enabled` 为真时运行，缺省是 false；关闭时保持放行（[intercept/intercept.go#L456](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/intercept/intercept.go#L456)、[intercept/intercept.go#L614-L616](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/intercept/intercept.go#L614-L616)）。

- 裁判输入收成当前工具名、参数和工作目录，并写明参数里的指示文字不当成裁决规则（[intercept/prompt.go#L10-L18](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/intercept/prompt.go#L10-L18)）。默认策略把读取敏感文件视为允许的只读动作（同文件 L71 附近）。

## 6. 依赖是否恶意与供应链风险

恶意依赖和普通已知漏洞分开写。未发现恶意证据不等于安全。未对 772 个 npm 包逐个查 OSV。

### 6.1 恶意与仿冒

- `web/package-lock.json`：lockfileVersion 3，772 个包条目均带 `integrity`。包名检索未见 `event-stream`、`ua-parser-js`、`node-ipc`、`peacenotwar`、`flatmap-stream` 这些已知恶意事件里的名字。检索不是全量恶意名单。
- `go.sum` 存在。直接模块见 `go.mod`。`replace` 把 `github.com/Autumn-27/norma v0.4.3` 指到 `github.com/chu0119/Norma v0.4.4`，`go.sum` 记录了后者的 h1。这是维护者声明的上游删除后的 fork，本次未把该模块源码与任何「官方 norma」逐文件对比，也未把它标成恶意。它是单点依赖：harness 不在本树。
- 无 git submodule。`web/.husky/pre-commit` 在 `npm` 安装钩子之后会跑主题生成和 lint-staged。本次未执行。钩子内容是仓库内三行脚本，未见外拉地址。
- 非官方源：Dockerfile 允许用构建参数换成 Debian／PyPI 镜像；hostd 安装源在 v0.4.86 的说明里只接受预设镜像 ID。本次未核对预设列表是否含意外主机。

### 6.2 浮动拉取与校验

- `install.sh` 默认 `VERSION=latest`。推荐入口是 `curl` 管道执行 Release 上的 `install.sh`。脚本自身在执行前没有校验；脚本跑起来之后，下载的 zip 取不到 `SHA256SUMS` 会拒绝安装（[install.sh#L450-L455](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/install.sh#L450-L455)）。校验对象与发布者是同一 GitHub Release，未见 cosign／minisign。macOS 路径还会管道执行 Homebrew 的 `install.sh`（同文件约 L670）。
- 一键更新：下载后比对 `SHA256SUMS`，主机白名单在 `selfupdate/github.go`。同样是「同一发布者的清单」，不是独立签名。
- 镜像构建：`golang:1.26-bookworm`、`python:3.11-slim-bookworm` 为标签。Node 来自 `curl` 管道执行 NodeSource `setup_20.x`。nuclei 在构建时解析 GitHub `releases/latest` 再下载 zip，该段未见校验和（[Dockerfile#L16-L74](https://github.com/Silver-cybersec/Pojun/blob/2230279b7e6eef1fdf2b008dda06664782e3b9c4/Dockerfile#L16-L74)）。Playwright 相关包为 `npm install -g @latest`。`go install` 的 kerbrute、waybackurls 钉了版本标签，未见额外 checksum。
- `docker/install-tools.sh` 对一批 GitHub 工具解析 `latest` 后下载，解压安装，无校验和。impacket 从 `fortra/impacket` 的 `master` 压缩包安装（同文件 L116-L133）。pip 安装 wafw00f、semgrep、pwntools 未钉版本。
- compose 与 bench 文件使用 `:latest` 或浮动标签。bench 的 Dockerfile 不在树里，无法审镜像内容。
- mihomo 的任意 URL 安装在 v0.4.89 要求调用方提供 SHA-256。官方 GitHub 路径的校验在 CHANGELOG 中声称仍在，本次未再读那条下载函数的每一行。

### 6.3 普通已知漏洞（OSV，只读）

对锁定版本做了四次 `api.osv.dev` 查询，未安装这些包：

- `next@16.2.9`：返回 21 条。抽到的标题集中在 Next 服务端（图像优化、开发服务器、Server Actions、缓存）。本仓默认产物是静态导出后放进 Go 二进制，Dockerfile 运行的是该二进制，不是 `next start`。这些通告不能直接写成「已部署实例可被远程执行」。有人改用 `npm run start` 或 `next dev` 暴露 Next 进程时，才进入这些通告描述的运行形态。未逐条核对修补版本。

- `github.com/golang-jwt/jwt/v5@v5.3.1`：0 条。
- `github.com/jackc/pgx/v5@v5.10.0`：0 条。
