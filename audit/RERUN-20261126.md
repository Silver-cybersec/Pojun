## 2. 架构

结论：一个 Go 进程同时是控制台、调度器和命令执行者；PostgreSQL 存任务与凭据；Docker 默认再把该进程放进 root 容器并挂上宿主机目录。授权范围挡住的是资产写回，不是 shell。

组件（已读）：

- `cmd/pojun`：HTTP 控制台与流量代理。裸二进制默认 `127.0.0.1:8787`（`cmd/pojun/main.go` 第 39–42 行）。镜像 CMD 为容器内 `:8787` 与 `:8788`（`Dockerfile` 第 130 行）。
- `server/server.go` 第 1181–1184 行：`/api/*` 经 `requireAuth`。放行的是 `/api/auth/*` 与 `/api/health`。健康检查只回 `ok`（第 1193–1194 行），版本在需登录的 `/api/version`。
- 登录用户名固定为 `POJUN` 或旧名 `ARTEX`（`server/auth.go` 第 561 行）。单管理员，无角色拆分。首次设密需要 `data/setup-token`（同文件第 366–441 行）。JWT 7 天，HS256，密钥在 `jwt.key`。
- `agent/`：planner、worker、main agent 的工具与提示。执行工具含 Bash（实现在 replace 模块 Norma，本单未读）、`job_start`、`http_request`、`run_script`、nuclei、回连监听。
- `intercept/` + `db/intercept_builtin_rules.go`：规则、模型研判、人工审批。默认只有 11 个工具名进入规则（见 PJ-M1）。
- `listener/`：TCP 回连，证据留存，不做完整 C2 会话管理。
- `traffic/`：记录用 MITM 代理，构造时无访问口令（`traffic/traffic.go` 的 `Open`）。
- `vault/`：另一类凭据加密存储。任务登录配置不走这里（PJ-L1）。
- `hostd/`：root 安装助手，Unix socket，只接受目录内工具 id（`hostd/recipe.go` 第 5–8 行）。
- `docker-compose.yml`：`postgres:16-alpine` 不发布端口；应用镜像默认 `ghcr.io/chu0119/pojun:latest`；`8787`/`8788` 发布到 `127.0.0.1`；挂载 `./data` 与 `./skills`。

信任与数据流：

- 操作员口令 → JWT → 全部 API（任务、工具、更新、宿主安装）。
- 模型工具调用 → 进程用户执行。容器内该用户是 root（PJ-H1）。
- 目标站口令/token/TOTP 以 JSON 进 PostgreSQL（PJ-L1）。战利品类凭据进 vault。
- 资产写回按任务 scope 分类；查询失败则放行写回（PJ-L3）。shell 不经过这道闸门。
- 工具回显包上不可信标签（`agent/untrusted.go` 第 10–17 行）。标签不阻止下一次工具调用。
- OTLP 只在显式设置 exporter 或端点时启用（`telemetry/telemetry.go` 第 31–45 行，`server/server.go` 第 198 行）。默认不外发 trace。
- 一键更新只访问 GitHub 主机白名单，并用同 Release 的 `SHA256SUMS`（`selfupdate/github.go` 第 20–35 行）。

已读到的绕过或误用：

- 不在 11 个默认名里的执行工具不进拦截规则；`local_exec=false` 也摘不掉 `job_start`（PJ-M1）。
- 研判失败/超时与人工审批超时可以放行（PJ-M2）。
- 分类查询失败时越界资产仍可能写上（PJ-L3）。
- 直接把控制台暴露到非回环，且客户端能伪造 `X-Forwarded-For` 时，登录全局锁不再封顶尝试次数（PJ-L2）。默认绑定已是回环。
